# 自然な3本指配置での指分離設定比較

Driver PR #1の[追加方針](https://github.com/Userd-uh/zmk-driver-iqs9151_mod/pull/1#issuecomment-5473378641)
に従う。広い/狭い指配置の比較は必須にせず、このパッドで普段使える自然な配置を固定する。
無理に指を広げて得た改善だけでは解決としない。

## 今回変更するもの

初期設定の0x11F1（Finger Split Factor）1バイトのみ。比較は現行3と近傍2/4。
メーカー仕様§7.6は分離設定の存在と0で分離無効となることを示しているが、ここでは
「大きいほど改善する」とは仮定しない。今回は分離を無効にする0を試さない。

| UF2（すべて左側用） | 読み戻しで確認する値 |
|---|---|
| lalapadgen2_left-split-3-baseline.uf2 | split=3（現行値） |
| lalapadgen2_left-split-2.uf2 | split=2 |
| lalapadgen2_left-split-4.uf2 | split=4 |

3種類は同じドライバー・キー設定・診断ログを使用する。
専用Kconfigは診断有効時だけ使われ、通常版は従来の3を維持する。
Confidenceしきい値20、感度、最大本数3、ゲイン、重心計算、ジェスチャー処理は変更しない。
これは修正の採用ではなく、改善方向を探す実験。値変更が逆効果になる可能性もある。

## 実機の手順

1. 左側へbaselineのUF2を書き込み、左側をUSB接続する。右側は通常版のまま。
   起動・校正が落ち着くまで全指を離す。settings_resetは使わない。
2. 同じレイヤー・アプリ・接続方法・姿勢を維持する。COM番号は前回COM9だったが、
   書込み後に変わる場合があるため確認する。
3. PowerShellで次を実行。最初の2秒は触らず、Recordingの表示を待つ。

```powershell
cd D:\project\keyboard\lalapad2\lalapad2
.\tools\capture-gesture-log.ps1 -Port COM9 -Seconds 60 -ExpectedReleases 3 -OutputPath .\gesture-split3.log
```

4. 自然な3本指配置で **3秒静止→2～3秒かけて横移動→全指を離す**。
5. 画面に **ALL FINGERS RELEASED** が出るまで次の試行を始めない。出た後さらに2秒待つ。
   同じ操作を計3回行い、残り時間は触らず待つ。操作中に早まって離脱表示が出た場合は、
   物理的には保持していたことをメモする（検出上の0と実際の離脱を混同しない）。
6. 最後にObserved full releases: 3となるか確認する。違う場合は独立3試行とみなさず、
   ログと実際の操作内容を共有する。繰り返し余計な接触を入れて数だけ合わせない。
7. 次にsplit2のUF2へ変更し、同じ手順で `gesture-split2.log` を取得。
   最後にsplit4で `gesture-split4.log` を取得する。ファイル名だけで条件を信じず、
   GCFGVのsplitとconfidence=20を確認する。GCFGのrcが0でない場合は比較条件を未確認とする。

まずbaselineの3独立試行を確認してから2/4へ進めてもよい。
USBポートを同時に他のシリアルツールで開かないこと。操作が不自然・暴走する場合は中止し、
通常版の左側UF2へ戻す。試験後は通常版の左側UF2へ復帰する。右側の書換えは不要。

## 判定に使う数値と限界

取得ファイルを共有すればこちらで集計する。手元でも標準Pythonのみで次を実行できる。

```powershell
python .\tools\analyze_gesture_log.py .\gesture-split3.log
```

- ログの12行構成、連番、時刻、指本数/信頼度と生フラグの整合性を先に確認。
  欠落・重複があれば維持率を算出しない。
- 各全指離脱までを1接触区間として集計。途中で記録が終わった区間を完了試行と数えない。
- fc=3のフレーム割合：無接触フレームを除く接触中の全フレームを分母とする。
  指を置く途中・離す途中も含まれ、センサーの認識正解率そのものではない。
- fc=3の時間割合・最長継続時間：次フレームまで直前の報告状態が続くとした推定値。
  イベント駆動なのでフレーム割合と時間割合は別物。最初の3秒の数値も出すが、
  実際に静止していたかはユーザーの操作申告と照合する。
- 3→2→1の回数は指離し動作も含むため、静止/移動途中か離脱中かをログ時刻・申告で区別する。
- 各有効座標スロットのarea範囲、confidence=0フレーム、強度範囲、Saturation発生を比較。
- 3点が報告されているフレームでは最も近い2点の距離を集計する。
  座標単位の距離でありmm換算ではない。confidence=0でも報告座標は参考として含む。

単回の良い結果で採用せず、独立3試行の再現性を確認する。スクロール量よりも3点の維持を優先。
今回の2/3/4で改善しなくても、それだけで物理限界とは断定しない。感度等の追加切り分けは
結果を見て別途一項目ずつ検討する。自然な配置で改善条件が見つからない場合に、
パッド寸法・電極構成とセンサーの分離能力の組合せも原因候補として扱う。

診断ログ・72バイトI2C読取りにはタイミング負荷がある。比較3種類で条件は揃えているが、
通常版での最終実用確認（1F/2Fの退行がないことも含む）は別途必要。
